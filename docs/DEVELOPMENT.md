# 양도소득세 신고 자동화 — 개발 문서

세무대리인용 **양도소득세(홈택스) + 개인지방소득세(위택스)** 신고·출력 자동화.
Python + Playwright(Chromium) + Tkinter. 로그인은 **항상 사용자가 직접**(자동화 안 함).

---

## 1. 구조

  pipeline.py              BrowserSession, run_phases, run_batch(여러 신고인), 병합
  ersfile.py               변환파일(.01/.Y13) 파싱 — 성명·주민번호·양도연월

### 실행 단계(7)
| # | KEY | 내용 |
|---|---|---|
| ① | `wetax_filing` | 위택스 지방세 파일변환신고 |
| ② | `hometax_filing` | 홈택스 양도세 파일변환신고 |
| ③ | `hometax_attach` | 홈택스 부속서류 제출 (**[수정]** 옵션 = 기존 제출분 삭제 후 재제출) |
| ④ | `hometax_docs` | 홈택스 접수증·신고서 출력 |
| ⑤ | `wetax_docs` | 위택스 신고서 출력 |
| ⑥ | `hometax_napbu` | 홈택스 납부서 출력 |
| ⑦ | `wetax_napbu` | 위택스 납부서 출력(가상계좌 대기 후) |

- phase는 **시작 시 하드 리셋**(홈 goto)으로 이전 상태와 격리.
- **여러 신고인**: 사람별로 ①~⑥ → 마지막에 ⑦만 전원 몰아서(가상계좌 대기 상쇄).
- 선행 신고 단계가 **이번 실행에서** 실패하면 후속 단계는 건너뜀(`DEPENDS_ON`).
- 한 명이 실패해도 다음 사람은 계속.

## 2. 핵심 노하우

### 2.1 PDF 저장 = 다운로드 방식 (Windows 저장창 없음)
- **홈택스(clipreport)**: `m_reportHashMap[k].pdfDownLoad()` → `page.expect_download()` → `save_as` → `%PDF` 검증.
  - 신고서 뷰어는 저장 버튼이 **UI에서 숨겨져 있을 뿐** API는 살아있다.
  - ⚠ `exportView()`로 저장 패널을 열면 **기본 형식이 Excel** → 패널 쓰지 말고 `pdfDownLoad()` 직접 호출.
- **위택스(OZ)**: `input.btnSAVEAS` 클릭 → 내보내기 창 → `#oztab_exportdlg_filetype`을 `Adobe PDF File(*.pdf)`로 변경(**기본값 `.ozd`!**) → [확인] → 다운로드.
  - OZ엔 clipreport 같은 JS API 없음(`OZViewer.Export` 등 전부 undefined). 툴바는 텍스트·alt 없는 아이콘이라 **클래스명으로** 잡을 것.
- 저장 전 `pdf_save.prepare_target`으로 기존 파일 삭제(덮어쓰기창·OneDrive 잠금 회피).
- 실패 시에만 기존 인쇄+`fill_and_save`로 폴백. `print`(실제 인쇄) 모드는 기존 경로.

### 2.2 화면 요소 탐색은 **폴링**으로
느린 PC·네트워크에서 아직 안 뜬 창/요소를 **한 번 보고 포기하면 그대로 실패**한다.
`wait_page(ctx, pred, timeout)` 사용. 빠른 환경에선 즉시 통과하므로 속도 손해 없음.
- ⚠ `wait_page`의 pred는 **동기/비동기 모두** 지원해야 한다(`inspect.isawaitable`).
  동기 lambda를 그냥 `await` 하면 TypeError가 except에 삼켜져 **영원히 못 찾음**.

### 2.3 WebSquare 함정
- 숫자 id(`hdGroup919`)는 매번 바뀜 → **텍스트/role 셀렉터**만.
- 메뉴는 메가메뉴 레이스 → `_open_and_click_submenu`(parent 대기 + 5회 재시도).
- **같은 popupID 창을 재사용** → "새 창 없음 ≠ 팝업 없음". `expect_page` 실패 시 기존 창을 찾는 폴백 필요.
- 모달마다 주민번호 칸 구조가 다름: 부속서류=앞6 text + 뒤7 password, 신고내역조회=단일 password(maxlength 20).
- 모달 확인/버튼 탐색은 **프레임당 JS 한 번**으로(요소별 await 왕복은 수 초 낭비).

### 2.4 홈택스 신고(②) 검증·제출
- 검증 완료 판정은 **`내용검증` 텍스트로만**. ⚠ `제출하러 가기` 버튼은 **검증 전에도 존재**해서 완료 신호로 쓰면 이전 신고인 화면 잔재를 보고 0초 만에 오판 → 엉뚱한 화면에서 제출하는 사고가 난다.
- 검증 클릭 후 **2.5초 안정화** 필수.
- **접수증 모달을 못 보면 실패로 처리**(예전엔 True를 돌려줘 뒷 단계가 전부 헛돌았다).
- **내용검증 경고(오류 아님)**: 검증결과내역이 `0(1)` 형태면 오류 0/경고 1.
  경고내역 → [엑셀 내려받기]로 `[경고내역]*.xls` 저장 후 모달 닫고,
  제출 시 뜨는 경고 알림은 **[취소]**를 눌러야 그대로 제출된다([확인]은 경고내역 보기).

### 2.5 개인정보 공개여부(④)
- **검증된 방식**: 공개여부 팝업(`공개여부` / `개인정보가 공개된` 포함 창)에서 Playwright로 **라벨 클릭 → [적용] 클릭**.
- ⚠ 라디오를 **JS로 직접 조작하면 안 된다** — WebSquare가 화면을 다시 그리며 `[적용]` 참조가 틀어져 클릭 실패(실제 회귀).
- ⚠ `개인정보…` 문구는 **신고서 보기 창에도 있다** → "조건에 맞는 첫 창 하나"만 보면 엉뚱한 창을 잡는다. **모든 창을 순회**할 것.
- 놓치면 서류가 **마스킹(주민번호 \*\*\*)** 된 채 저장됨 → 실패 시 경고 로그.

### 2.6 파일명·병합
- `[접수증]{이름}` / `[신고서]{이름}_{목록명|지방세}` / `[납부서]{이름}_{양도소득세|지방세}_{YY.MM.DD}`
- 이름은 `include_name`일 때만. 납부기한 fetch: 홈택스=납부서목록 표, 위택스=신고내역 행(**'출력물 보기' 앵커의 closest(tr)** — 전체 tr 순회는 래퍼 tr을 잡아 다른 사람 날짜를 가져옴).
- 병합: 접수증 → 홈택스 신고서들(저장순) → 지방세 신고서 → `[접수증&신고서]{이름}.pdf`.
  **이번 실행에서 접수증 + 양도세 신고서 1건 이상 + 지방세 신고서 1건 이상이 모두 있을 때만**
  병합한다. 단계 성공 여부만 믿지 말고 **파일 자체를 센다**(#17 — 신고서 0건이 '성공'으로
  보고돼 접수증+지방세만 병합되고 원본이 지워졌다). ④만 다시 돌리면 지방세가 없어 병합을
  건너뛴다 → 기존 병합본을 불완전한 것으로 덮지 않는다.
- **병합 후 개별 파일은 지우지 않는다** — 병합에 성공하면 **항상** `{PDF저장폴더}/병합전파일/`로
  **옮긴다**(별도 옵션 없음 — 병합을 켰다는 건 본 폴더엔 병합본을 보겠다는 뜻이고, 개별 파일은
  대조용으로 곁에 있으면 된다). 병합을 끄면 개별 파일은 본 폴더에 그대로 남는다.
  예전엔 '병합 후 개별 원본 삭제' 옵션으로 지웠는데, 병합이 맞게 됐다는 전제 위의 삭제라
  #17처럼 전제가 틀리면 되돌릴 방법이 없었다.
  재실행하면 같은 이름을 덮어쓰고(중복 안 쌓임), 이전 파일이 뷰어에 열려 있으면 `_HHMMSS`를 붙여 옮긴다.
  이동이 실패한 파일은 본 폴더에 그대로 남긴다(어떤 경우에도 지우지 않는다).
- ⚠ **서류 출력 단계는 하나라도 실패하면 단계 실패**(`hometax_docs`·`wetax_docs`). 예전엔 일부만
  저장돼도 `ok=True`였다. 저장된 파일은 `outputs`에 남고, 실패 표시는 '다시 돌려라'는 신호다.
- ⚠ **신고서 목록 0건 = 실패.** 양도세 신고서는 최소 1건(과세표준 신고 및 납부계산서)이 반드시
  있다. 뷰어 창을 못 찾아도 실패로 기록한다(예전엔 기록 없이 돌아가 '성공'이 됐다).
  0건이면 `report_dump_*.txt`(PDF 저장 폴더)에 뷰어 구조를 남긴다 — **덤프 첫 줄의 viewer URL**과,
  계산서/명세서/신고서 문구가 **직접 붙은** 모든 요소의 태그·크기(0x0=숨김)·텍스트.
  #18은 이 덤프 첫 줄(본 화면 URL)로 단번에 확정됐다.
- ⚠ **신고서 뷰어는 '신고서 목록' 문구만으로 고르면 안 된다**(#18). 2026-10 홈택스가 신고내역 조회
  표에 접근성 설명(`제출한 신고서 목록을 조회할 수 있습니다.`)을 넣어 **본 화면**이 먼저 걸렸다.
  → **본 화면(page)은 제외 + 신고서 항목이 1건 이상 '보이는' 창만** 뷰어로 인정(최대 20초 대기).
  창을 '고르는 조건'과 '그 창에서 할 일'을 같은 것으로 묶으면, 엉뚱한 창이 걸려도 조건을 통과 못 한다.
- ⚠ 같은 이름 병합본을 **PDF 뷰어(알PDF 등)가 열어두면 덮어쓰기가 거부**된다(`Errno 13`).
  재실행 때만 터지므로 첫 실행에선 안 보인다. → 거부됐을 때만 `_HHMMSS` 붙여 저장.

### 2.7 위택스 납부서 대기(⑦)
가상계좌는 **납부서 PDF 문서 안에 인쇄되는 값**이라 프로그램이 생성 여부를 알 수 없다
(링크·버튼은 신고 즉시 생김 → 링크 확인은 무의미).
→ 시간으로 기다리되 대기 중 사용자가 **[지금 출력]**(즉시 진행) / **[+1분]**(연장)으로 개입.

### 2.8 부속서류 첨부(③) — 주입 타이밍
**파일 입력칸이 보여도 바로 꽂으면 안 된다.** 입력칸은 팝업 초기화 도중 이미 존재하는데,
팝업 자신의 첨부목록 조회(`wqAction.do?actionId=ATTCMGAA001R03`)가 아직 날아가는 중이다.
먼저 꽂으면 홈택스 JS가 정상적으로 받아 그리드에 그리지만, 뒤이어 도착한 **조회 응답이
그리드를 서버 결과(빈 목록)로 재바인딩**하며 방금 넣은 행을 통째로 덮는다.
→ `wqAction` 응답이 **1.5초간 없을 때까지 대기한 뒤 주입**(최대 10초), 그래도 사라지면
   조회 완료를 다시 기다려 **1회 재주입**. 중복은 홈택스가 막는다("동일한 파일은 한 번만").

- 라이브 진단 근거(2건 동일): 주입 0.2초 뒤 `matched=6/6`, `input.files=0`(JS가 정상 인계),
  이후 소멸. **JS오류 0·경고창 0·실패응답 0**, 구간 내 서버 호출은 그 조회 1건뿐.
- 등록 0개로 중단될 때 `attach_dump_*.txt`(PDF 저장 폴더)에 타임라인·콘솔·JS오류·네트워크·
  알림을 남긴다. 소멸 구간은 0.5초 폴링으론 못 보므로 **200ms 간격**으로 훑는다.
- 실제 파일 업로드(K Upload 진행창)는 **[부속서류 제출하기] 이후**에 일어난다 — 첨부 시점의
  목록은 클라이언트 그리드일 뿐이다.

### 2.9 부속서류 수정 — ③의 [수정] 옵션
계산이 틀렸거나 서류를 잘못 냈을 때. **제출 절차는 ③과 같고 앞에 '기존 제출분 삭제'만 붙는다.**

**별도 단계로 두지 않는다.** 두 줄이면 '둘 중 하나만 켜기' 규칙을 따로 만들어 지켜야 하고
(셀 단위까지 막으려면 규칙이 또 는다), 사용자에겐 별개 작업처럼 보인다. 실제로는 같은 작업
앞에 삭제가 붙는 것뿐이므로 **③의 하위 옵션(`Inputs.replace_attachments`)** 으로 둔다.

화면 상태는 **조회 후 자동 판별**한다(`attach_state`: `[제출내역보기]`=submitted / `[첨부하기]`=new).

| 화면 | [수정] | 동작 |
|---|---|---|
| 미제출 | 꺼짐/켜짐 | 그냥 제출 |
| **이미 제출됨** | **꺼짐** | **중단** + "이미 제출된 건 — [수정]을 켜고 다시 실행하세요" |
| 이미 제출됨 | 켜짐 | 삭제 → 화면 재진입 → ③ 경로로 재제출 |

⚠ 이 판별이 없으면 이미 제출된 건에서 `[첨부하기]`를 못 찾아 **정체불명의 실패**로 끝난다
(옵션 도입 전 실제 동작). 체크를 안 켜면 **절대 지우지 않는다**.
- 이미 제출한 신고건은 조회 결과의 **[첨부하기] 자리에 [제출내역보기]**가 뜬다(둘은 배타적).
  → 제출목록 모달 → 선택 라디오 → **[선택한 부속서류 삭제]** → '정상 삭제' 알림 확인.
  **전부 지우면 다시 [첨부하기]로 돌아온다**(사용자 확인) → 재제출은 ③ 경로를 그대로 탄다.
- ⚠ **선택이 라디오(단일 선택)라 한 번에 한 건씩만** 지워진다 → 목록이 빌 때까지 반복.
  건수가 안 줄면 즉시 중단한다(무한 반복 방지).
- ⚠ 모달 탐색은 **제목 텍스트로 좁힌다** — 바깥 '신고 부속·증빙서류 제출'도 같은 `.w2window`라
  클래스만으로는 구분되지 않는다.
- ⚠ 삭제하면 알림이 **두 번** 뜬다: '정상 삭제 되었습니다' → (목록 새로고침) **'조회가 완료되었습니다'**.
  뒤엣것은 '삭제'가 안 들어간 문구라 같은 조건으로는 안 걸린다 → 따로 닫아야 하고,
  안 닫으면 알림이 모달을 덮은 채 남아 **[닫기]와 다음 클릭이 전부 막힌다**(라이브 확인).
- ⚠ 라디오는 **frame당 JS 1회**로 탐색+scrollIntoView(1회)+클릭. Playwright click()을 쓰면
  WebSquare가 input 위에 꾸밈 요소를 덮어둔 탓에 actionability 검사가 실패해
  **스크롤을 반복 시도하고 화면이 위아래로 흔들린다**(2.11).
- **삭제만 하고 끝나면 부속서류 없는 신고건이 남는다** → 삭제 단독 실행 단계는 만들지 않고,
  이 phase가 삭제와 재제출을 한 덩어리로 수행한다. 재제출은 `hometax_attach.run`을 그대로
  호출해 ③의 검증된 경로를 재사용(2.8의 조회 안정화·재주입 포함).
- 삭제는 실패하면 **재제출하지 않고 중단**한다(기존 서류와 섞이면 더 나쁘다).
- GUI에선 ③ 행 라벨 옆 작은 체크박스(`MiniCheck`). 기본 꺼짐이고 **settings.json에 저장하지
  않는다** — 켠 채로 잊고 다음 날 그대로 도는 것이 가장 위험하다(재시작하면 꺼짐).
  단계 토글을 끄면 체크박스도 흐려진다.

### 2.10 GUI — 경과 시간 타이머
푸터 오른쪽, 상태 문구 왼쪽에 `0:00` / `4:12` / `1:02:30` 형식으로 표시(1시간 넘으면 시:분:초).

- **상태 문구(`status_var`)에 얹지 않는다.** 그 칸은 `실행 중…`, `가상계좌 대기 12/60초`,
  `완료 — …`로 계속 바뀌어 서로 덮어쓴다. 별도 라벨(`elapsed_var`)을 둔다.
- **별도 `after` 타이머를 만들지 않는다.** 이미 100ms로 도는 `_poll`에 `_tick_elapsed()`를
  얹는다 — 타이머를 따로 돌리면 중단·종료·창닫힘마다 취소 관리가 하나 더 는다.
  표시 문자열이 바뀔 때만 `set()` 하므로 실제 갱신은 초당 1회.
- 글꼴은 **고정폭(MONO)** — 숫자 폭이 달라 라벨이 흔들리는 것 방지.
- 기준 시각은 `time.monotonic()`. 벽시계(`datetime`)를 쓰면 시간 동기화·서머타임에
  경과가 튄다.
- 종료(`done`)와 **[중단]** 양쪽에서 `_finish_elapsed()`로 값을 고정하고 총 소요를 로그에 남긴다.
  ⚠ 중단에서도 부르는 이유: 취소가 코루틴 시작 전에 걸리면 `done`이 영영 오지 않아
  타이머만 계속 돈다. 두 번 불려도 `_run_started=None` 가드로 한 번만 집계된다.

### 2.11 화면이 위아래로 흔들릴 때 (반복 발생 — 원인은 항상 같다)
**Playwright click()/check()의 스크롤 재시도**다. WebSquare는 `input` 위에 꾸밈 요소를 덮어두는데,
그러면 actionability 검사(가려지지 않았는지)가 실패하고 Playwright는 **요소를 다시 스크롤해
재시도**한다. 이걸 여러 방법으로 연달아 시도하면(라디오 → force → 부모 셀 …) 시도마다
스크롤이 걸려 화면이 요동친다.

→ **탐색부터 클릭까지 frame당 JS 한 번**으로 끝낸다. `scrollIntoView({block:'center'})`는 **1회만**.
```js
const vis = e => { const r = e.getBoundingClientRect(); const s = getComputedStyle(e);
    return r.width > 1 && r.height > 1 && s.display !== 'none' && s.visibility !== 'hidden'; };
target.scrollIntoView({block: 'center'});   // 딱 한 번
if (!target.checked) target.click();
```
적용처: `ingunbi_auto.jigup_submit`(제출 확인 체크박스), 본 프로젝트 `_LIST_MODAL_JS`(삭제 라디오),
`_try_click_modal_confirm`(모달 확인).

⚠ 단, **JS 조작 뒤에는 다른 요소의 참조가 틀어질 수 있다**(#11 — WebSquare가 화면을 다시 그린다).
JS로 만진 다음에 누를 버튼은 **그때 새로 찾을 것**(미리 잡아둔 locator를 재사용하지 말 것).

(b) 그러나 **검증된 동작을 임의로 바꾸지 말 것** — JS 조작·헬퍼 도입이 회귀를 만들었다(#11).
(c) 홈택스는 화면 잔재가 남으므로 **완료 신호를 그 단계에서만 나오는 것으로** 골라야 한다(#6).
(d) **요소가 보인다 ≠ 화면이 준비됐다** — #13은 입력칸이 초기화 도중 이미 존재해서 난 사고다.
증상만 보면 "첨부가 안 된다"였지만 실제로는 **너무 빨라서** 난 문제였다. 에러가 하나도
없다면(JS오류·경고창·실패응답 전무) 거부가 아니라 **정상 렌더가 덮은 것**을 의심할 것.
(e) **창을 문구로 고르면 그 문구는 언젠가 다른 창에도 생긴다**(#11·#18). 고르는 조건에
'그 창에서 실제로 할 일이 가능한가'(목록이 보이는가)를 넣을 것. 그리고 **'0건'을 성공으로 넘기지
말 것** — #17은 탐색 실패가 성공 보고로 둔갑해 안전장치를 통과한 사고다.
