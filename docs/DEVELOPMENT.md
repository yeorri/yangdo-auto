# 양도소득세 신고 자동화 — 개발 문서

세무대리인용 **양도소득세(홈택스) + 개인지방소득세(위택스)** 신고·출력 자동화.
Python + Playwright(Chromium) + Tkinter. 로그인은 **항상 사용자가 직접**(자동화 안 함).

---

yangdo_auto.spec           PyInstaller onedir 빌드(Chromium 미동봉)

  ersfile.py               변환파일(.01/.Y13) 파싱 — 성명·주민번호·양도연월

## 2. 핵심 노하우

### 2.1 PDF 저장 = 다운로드 방식 (Windows 저장창 없음)
- **홈택스(clipreport)**: `m_reportHashMap[k].pdfDownLoad()` → `page.expect_download()` → `save_as` → `%PDF` 검증.
  - 신고서 뷰어는 저장 버튼이 **UI에서 숨겨져 있을 뿐** API는 살아있다.
  - ⚠ `exportView()`로 저장 패널을 열면 **기본 형식이 Excel** → 패널 쓰지 말고 `pdfDownLoad()` 직접 호출.
- **위택스(OZ)**: `input.btnSAVEAS` 클릭 → 내보내기 창 → `#oztab_exportdlg_filetype`을 `Adobe PDF File(*.pdf)`로 변경(**기본값 `.ozd`!**) → [확인] → 다운로드.
  - OZ엔 clipreport 같은 JS API 없음(`OZViewer.Export` 등 전부 undefined). 툴바는 텍스트·alt 없는 아이콘이라 **클래스명으로** 잡을 것.
- 저장 전 `pdf_save.prepare_target`으로 기존 파일 삭제(덮어쓰기창·OneDrive 잠금 회피).
- 실패 시에만 기존 인쇄+`fill_and_save`로 폴백. `print`(실제 인쇄) 모드는 기존 경로.

### 2.2 화면 요소 탐색은 **폴링**으로
느린 PC·네트워크에서 아직 안 뜬 창/요소를 **한 번 보고 포기하면 그대로 실패**한다.
`wait_page(ctx, pred, timeout)` 사용. 빠른 환경에선 즉시 통과하므로 속도 손해 없음.
- ⚠ `wait_page`의 pred는 **동기/비동기 모두** 지원해야 한다(`inspect.isawaitable`).
  동기 lambda를 그냥 `await` 하면 TypeError가 except에 삼켜져 **영원히 못 찾음**.

### 2.3 WebSquare 함정
- 숫자 id(`hdGroup919`)는 매번 바뀜 → **텍스트/role 셀렉터**만.
- 메뉴는 메가메뉴 레이스 → `_open_and_click_submenu`(parent 대기 + 5회 재시도).
- **같은 popupID 창을 재사용** → "새 창 없음 ≠ 팝업 없음". `expect_page` 실패 시 기존 창을 찾는 폴백 필요.
- 모달마다 주민번호 칸 구조가 다름: 부속서류=앞6 text + 뒤7 password, 신고내역조회=단일 password(maxlength 20).
- 모달 확인/버튼 탐색은 **프레임당 JS 한 번**으로(요소별 await 왕복은 수 초 낭비).

### 2.4 홈택스 신고(②) 검증·제출
- 검증 완료 판정은 **`내용검증` 텍스트로만**. ⚠ `제출하러 가기` 버튼은 **검증 전에도 존재**해서 완료 신호로 쓰면 이전 신고인 화면 잔재를 보고 0초 만에 오판 → 엉뚱한 화면에서 제출하는 사고가 난다.
- 검증 클릭 후 **2.5초 안정화** 필수.
- **접수증 모달을 못 보면 실패로 처리**(예전엔 True를 돌려줘 뒷 단계가 전부 헛돌았다).
- **내용검증 경고(오류 아님)**: 검증결과내역이 `0(1)` 형태면 오류 0/경고 1.
  경고내역 → [엑셀 내려받기]로 `[경고내역]*.xls` 저장 후 모달 닫고,
  제출 시 뜨는 경고 알림은 **[취소]**를 눌러야 그대로 제출된다([확인]은 경고내역 보기).

### 2.5 개인정보 공개여부(④)
- **검증된 방식**: 공개여부 팝업(`공개여부` / `개인정보가 공개된` 포함 창)에서 Playwright로 **라벨 클릭 → [적용] 클릭**.
- ⚠ 라디오를 **JS로 직접 조작하면 안 된다** — WebSquare가 화면을 다시 그리며 `[적용]` 참조가 틀어져 클릭 실패(실제 회귀).
- ⚠ `개인정보…` 문구는 **신고서 보기 창에도 있다** → "조건에 맞는 첫 창 하나"만 보면 엉뚱한 창을 잡는다. **모든 창을 순회**할 것.
- 놓치면 서류가 **마스킹(주민번호 \*\*\*)** 된 채 저장됨 → 실패 시 경고 로그.

### 2.6 파일명·병합
- `[접수증]{이름}` / `[신고서]{이름}_{목록명|지방세}` / `[납부서]{이름}_{양도소득세|지방세}_{YY.MM.DD}`
- 이름은 `include_name`일 때만. 납부기한 fetch: 홈택스=납부서목록 표, 위택스=신고내역 행(**'출력물 보기' 앵커의 closest(tr)** — 전체 tr 순회는 래퍼 tr을 잡아 다른 사람 날짜를 가져옴).
- 병합: 접수증 → 홈택스 신고서들(저장순) → 지방세 신고서 → `[접수증&신고서]{이름}.pdf`.
  **접수증이 없거나 출력 단계가 실패하면 병합하지 않는다**(서류 빠진 병합본 + 원본 삭제 사고 방지).
- ⚠ 같은 이름 병합본을 **PDF 뷰어(알PDF 등)가 열어두면 덮어쓰기가 거부**된다(`Errno 13`).
  재실행 때만 터지므로 첫 실행에선 안 보인다. → 거부됐을 때만 `_HHMMSS` 붙여 저장.

### 2.7 위택스 납부서 대기(⑦)
가상계좌는 **납부서 PDF 문서 안에 인쇄되는 값**이라 프로그램이 생성 여부를 알 수 없다
(링크·버튼은 신고 즉시 생김 → 링크 확인은 무의미).
→ 시간으로 기다리되 대기 중 사용자가 **[지금 출력]**(즉시 진행) / **[+1분]**(연장)으로 개입.

### 2.8 부속서류 첨부(③) — 주입 타이밍
**파일 입력칸이 보여도 바로 꽂으면 안 된다.** 입력칸은 팝업 초기화 도중 이미 존재하는데,
팝업 자신의 첨부목록 조회(`wqAction.do?actionId=ATTCMGAA001R03`)가 아직 날아가는 중이다.
먼저 꽂으면 홈택스 JS가 정상적으로 받아 그리드에 그리지만, 뒤이어 도착한 **조회 응답이
그리드를 서버 결과(빈 목록)로 재바인딩**하며 방금 넣은 행을 통째로 덮는다.
→ `wqAction` 응답이 **1.5초간 없을 때까지 대기한 뒤 주입**(최대 10초), 그래도 사라지면
   조회 완료를 다시 기다려 **1회 재주입**. 중복은 홈택스가 막는다("동일한 파일은 한 번만").

- 라이브 진단 근거(2건 동일): 주입 0.2초 뒤 `matched=6/6`, `input.files=0`(JS가 정상 인계),
  이후 소멸. **JS오류 0·경고창 0·실패응답 0**, 구간 내 서버 호출은 그 조회 1건뿐.
- 등록 0개로 중단될 때 `attach_dump_*.txt`(PDF 저장 폴더)에 타임라인·콘솔·JS오류·네트워크·
  알림을 남긴다. 소멸 구간은 0.5초 폴링으론 못 보므로 **200ms 간격**으로 훑는다.
- 실제 파일 업로드(K Upload 진행창)는 **[부속서류 제출하기] 이후**에 일어난다 — 첨부 시점의
  목록은 클라이언트 그리드일 뿐이다.

## 3. 문제 해결 기록

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| 1 | clipreport `check3Dom` undefined | 인쇄방식 레이어 DOM 미초기화 | `printWindowView()` → select에 `change` 발화 → `mRe_printExportInfo()` |
| 2 | 위택스 납부기한이 다른 사람 것 | 전체 tr 순회가 테이블 래퍼 tr을 먼저 잡음 | '출력물 보기' 앵커의 `closest('tr')` 기준 |
| 3 | 부속서류 빈 제출이 성공으로 보고 | 제출 클릭만 하면 True | 등록 N/M 확인 + 완료 메시지 확인 |
| 4 | 첨부 순서가 0,1,10,2… | 문자열 정렬 | 자연 정렬(숫자 인식) |
| 5 | 첨부 10개인데 9/10 집계 | 목록 표시가 말줄임(…) | 공백 제거 + 프리픽스 12→10→8→6자 매칭 |
| 6 | 제출 안 됐는데 성공 보고 | `제출하러 가기`를 검증 완료 신호로 사용 | `내용검증`만으로 판정 + 2.5초 안정화, 접수증 미확인 시 실패 |
| 7 | 경고 있으면 제출 실패 | 경고 알림이 떠 `전자파일 제출하기`를 못 찾음 | 경고내역 엑셀 저장 후 알림에서 **[취소]** |
| 8 | 접수증·납부서 실패 | `wait_page`가 동기 pred를 항상 await → 영원히 못 찾음 | `inspect.isawaitable` 분기 |
| 9 | 납부서 1건 실패 | 접수증 창이 안 닫혀 popupID 재사용 → 새 창 이벤트 없음 | 기존 clipreport 창 재사용 폴백 |
| 10 | 첨부 팝업이 떴다가 바로 닫힘 | 파일 입력칸을 1회만 탐색 → 실패 반환 → 호출측이 close | 입력칸 등장까지 폴링(12초) |
| 11 | 개인정보 공개 [적용] 실패 | 라디오를 JS로 조작 / 첫 창 하나만 탐색 | 원본(라벨 클릭) 복원 + 모든 창 순회 |
| 12 | 서류 저장 시 다른 창 쓰면 실패 | Windows 저장 다이얼로그 포커스 문제 | **다운로드 방식으로 전환**(2.1) |
| 13 | 부속서류 첨부가 목록에서 사라짐 | 팝업 초기 목록조회(`ATTCMGAA001R03`)가 **주입보다 늦게 도착**해 그리드를 빈 서버결과로 재바인딩 | 조회가 1.5초간 조용해진 뒤 주입 + 사라지면 1회 재주입(2.8) |
| 14 | 병합 `Permission denied` | 같은 이름 병합본을 PDF 뷰어가 열어둠 | 거부됐을 때만 시각 붙인 새 이름으로 저장 |

**교훈**: (a) "1회만 찾고 포기"가 반복된 실패 원인 — 탐색은 폴링으로.
(b) 그러나 **검증된 동작을 임의로 바꾸지 말 것** — JS 조작·헬퍼 도입이 회귀를 만들었다(#11).
(c) 홈택스는 화면 잔재가 남으므로 **완료 신호를 그 단계에서만 나오는 것으로** 골라야 한다(#6).
(d) **요소가 보인다 ≠ 화면이 준비됐다** — #13은 입력칸이 초기화 도중 이미 존재해서 난 사고다.
증상만 보면 "첨부가 안 된다"였지만 실제로는 **너무 빨라서** 난 문제였다. 에러가 하나도
없다면(JS오류·경고창·실패응답 전무) 거부가 아니라 **정상 렌더가 덮은 것**을 의심할 것.

## 4. 배포

```bash
# 1) updater.py CURRENT_VERSION, version.json 갱신 후 push
pyinstaller yangdo_auto.spec --noconfirm --clean
cp dist_readme.txt dist/YangdoAuto/사용안내.txt
# 2) dist/YangdoAuto 를 zip → gh release create vX.Y.Z YangdoAuto_vX.Y.Z.zip
```
- Chromium 미동봉(첫 실행 시 `%LOCALAPPDATA%\ms-playwright`에 1회 설치) → zip 약 58MB.
- frozen이면 `.profile`은 `%LOCALAPPDATA%\YangdoAuto`, `PLAYWRIGHT_BROWSERS_PATH`를 명시 선점해야 함.
- 저장소가 Private이면 업데이트 확인·릴리즈 다운로드가 동작하지 않음.
